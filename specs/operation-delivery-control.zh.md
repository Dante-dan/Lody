# 操作结果展示与自动续聊控制

Status: draft
Translation: pending

## 场景与目标

一个会话在离线期间完成多个委派操作。恢复后，用户应能看到所有结果；
点击停止后，后面的完成通知不能立即再次唤醒代理，重启也不能解除暂停。
本草案记录停止后的投递契约。实现状态与验证范围见末尾；草案状态不等于发布验收。

## 停止与恢复

- 用户点击停止表达两个意图：取消指定回合，以及暂停该会话的操作完成自动续聊。
  内部取消、编辑并重发、取消单个委派操作、打断并发送、移除本地项目不隐含第二个意图；RPC 与持久兜底必须保留这个区别。
- 暂停有持久记录，并在取消当前回合、释放其执行所有权之前建立阻挡。
  即使当时没有运行中的回合，也可以暂停自动续聊。
- Stop 到达时若已由自动完成回复接替，且历史证明期间没有新用户输入，则暂停后续投递并取消该接替回合；不得跨越新用户输入。读取历史后必须重新核对当前执行来源。
- 旧停止请求不得取消新回合，重复停止不得阻挡后来的新工作。不增加停止编号；已有队列中的用户消息在停止后实际提交时，也可以携带已就绪结果。
  停止和自动启动并发时必须有明确顺序：停止先获准则不得启动；启动先获准则取消该回合并阻挡后续启动。
- 暂停期间，已有队列和旧工作后来完成的操作都继续保存结果、更新已有卡片；不得自动调用代理。
  不逐条追加抢占注意力的新卡片，不自动滚动，显示一处“有 N 项结果，随下条消息提供给 AI”。
- 下次实际提交给代理的人类消息，携带当时已经完成且尚未提供给代理的旧结果，一次处理。
  不先处理结果再发送用户消息，也不在用户消息之后逐条恢复旧队列。
  当前用户指令决定如何使用结果；结果是带来源的参考资料，不是继续旧任务的指令。
- 旧工作在此次输入快照之后才完成的结果，仍等待下一条人类消息，不在本轮结束时自动唤醒。
  新人类回合委派的新工作保留正常自动续聊能力。工作归属按持久因果标识区分，不能用完成时间猜测。
- 人类消息包括实际被接受的发送或 steer；草稿、被取消的排队消息、自动重试和操作通知不算恢复。
  实现计划、创建 PR、修复 CI 等用户点击的快捷操作也遵从本次携带结果的选择；后台容量重试明确不携带。
  用户也可显式请求处理积压而不输入正文；这一入口遵守同样的单次输入和旧结果等待规则。
- 普通回复正常结束不删除、不暂停其他操作通知。停止 requester 不自动取消其目标会话。

## 两条独立的处理路径

```text
操作完成并持久化
  ├─ 展示结果：按稳定操作标识写入或更新卡片 → 本地持久化确认
  └─ 请求自动续聊：等待可运行条件 → 检查暂停状态 → 认领 → 启动 → 结算
```

展示结果不得依赖自动续聊成功。已展示、未运行的结果不能冒充代理已处理。
暂停不是错误，也不消耗重试次数。结果保存沿用既有保留策略，不承诺无限保存；
清理不能因暂停或展示成功而提前删除唯一结果副本。

恢复进程必须先加载控制状态，再扫描可运行通知。认领与代理启动前均需重新检查状态；
异步准备期间发生暂停时，应释放未启动的认领，保留结果。已经开始但结算未知的任务
仍按既有 uncertain 规则处理，不能因为恢复而重放。

## 后续优化：合并积压

停止后的结果首先合并到下一次人类输入，与无人干预时合并自动续聊批次是不同路径。
人类输入沿用本次选择的模型和配置，结果保持独立来源与访问权限，不逐条恢复旧冻结配置。
不得把结果伪装为用户手写文字；输入界面显示携带结果的数量，并允许本次不携带。
按实际提交边界冻结结果成员，将这组成员绑定到稳定的用户 Turn；重复调度不能重复附加。
结果较多时发送有界摘要和可检索引用，不以完整内容阻塞用户发送，也不为超限内容自动拆成多轮。
实现上每次输入的附加内容最多 68 KiB，结构信息仍放不下的部分继续待处理；完整结果不被摘要覆盖。
检索引用必须确实可用；没有结果读取能力时不能只提供无法打开的标识。

成员绑定不是消费：提交前失败要释放或重试同一绑定，确认开始后的取消不自动重放，
提交结果未知则保留 uncertain 证据和手动处理入口。不能在 UI 点击发送时就把全部结果标为已处理。
对于 steer，只有支持同一输入携带附加上下文且代理确认接受时才结算；否则保持结果待处理。

在会话空闲边界选取当时已就绪的一组兼容结果，冻结成员并持久化批次标识，发起一次续聊。
此自动路径仅适用于未被停止的工作；之后到达的结果归下一批，不使用固定等待时间收集通知。
用户待发送消息保持优先。
只有 requester 身份、冻结执行配置和委派链约束兼容的结果才可合并；不跨会话合并。
提示词须有总长度上限，保留逐操作标识、结果引用和截断说明。

批次须保留每个操作的独立展示和结算，使用稳定 Assistant 标识与启动认领。
用户取消已启动批次后，该次输入不自动重放；未选入批次的通知继续暂停。
此优化依赖新的批次执行契约，不能直接在现有逐操作循环外拼接提示词。

## 验收

使用显式屏障、注入时钟与重开同一测试数据库验证：

1. 多条积压中停止第一条，后续代理输入为零；所有结果仍可读取和展示。
2. 在空闲、认领前、写历史后、启动检查前、回复结束后分别停止，均符合规定顺序。
3. 停止成功后重启仍暂停；旧工作新完成结果不唤醒；下次人类输入和待处理结果只产生一次输入。
4. 旧工作迟到结果继续等待，新人类回合的新工作可正常续聊；旧取消请求不能取消新回合。
5. 内部取消和正常回复结束不改变暂停状态；用户消息保持优先。
6. 状态写入失败不能报告持久暂停成功；崩溃恢复不能重放 started/uncertain 工作。
7. 合并阶段另验批次成员持久化、长度限制、配置隔离和崩溃后的逐项结算。
8. 发送失败、取消排队、steer 拒绝、重复调度不丢结果、不重复附加；已开始或未知输入不自动重放。
9. 用户更换模型、改变任务、选择不携带结果时尊重本次选择，旧结果不能抢先执行旧指令。
