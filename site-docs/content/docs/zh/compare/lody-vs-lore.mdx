# Lody 与 Lore：现场交接 vs 分享链接

**分享链接**发布的是一份编程 Agent 会话记录。**现场交接**是把同事请进**同一个**会话，让对方继续聊、继续看 diff，并在同一个 Worktree 里接着改。

[Lore](https://lore.link/share) 是前一种做法的常见例子：渲染好的 thread，可以查看，或 fork 进一次**新的** Agent 运行。[Lody](/zh/docs/session-handoff) 做的是后一种：同事打开工作空间里已有的会话，接着往下做。

这一页只把定义钉清楚。操作步骤见[共享并交接 Agent 会话](/zh/docs/session-handoff)。团队工作空间见[团队功能](/zh/docs/team)和[并行 Coding Agents](/zh/docs/parallel-agents)。

<Callout title="定义">
Lore 式分享链接或对话导出，都不是 Lody 交接。查看者不会加入你正在跑的会话，也不会拿到原来的 Worktree。交接要求对方已是工作空间成员，并遵守交接页上的机器 / 项目共享规则——不是谁拿到 URL 都能打开。
</Callout>

## 两件不同的事

团队分享 Agent 工作的方式很多，大多数停在「你看一下」。

| 做法 | 对方能做什么 | 是否同一个现场会话 |
| --- | --- | --- |
| 截图 | 看对话的一张图 | 否 |
| Markdown / 对话导出 | 把静态文本贴进新对话 | 否——只能重来 |
| ChatGPT 式分享链接 | 阅读对话快照 | 否 |
| [Lore](https://lore.link/share) | 查看渲染好的 thread（提示词、工具调用、改过的文件），或把上下文 fork 进**新的** Agent 会话 | 否——原会话仍停在原来的运行环境 |
| [SpecStory](https://docs.specstory.com/cloud/session-sharing) | 打开保存下来的历史，或公开的查看链接 | 否——查看者不会加入正在跑的会话 |
| **Lody 交接** | 打开已有[会话](/zh/docs/session)，继续聊，审阅实时 [Diff](/zh/docs/diff-viewer)，并在同一个 [Worktree](/zh/docs/worktrees) 里接着改 | **是** |

如果只需要留档，Lody 也可以[把对话复制成 Markdown](/zh/docs/copy-md)。只复制会话 URL、却没有把会话共享给团队，也不会授予访问权限——这条链接对所有者仍然有效。

## Lore 适合做什么

Lore 把「分享链接」这件事做得很清楚：

- 把一次会话变成**可查看的记录**——提示词、工具调用、改过的文件。
- 对方不必加入你的工作空间就能阅读。
- 有些流程可以把蒸馏后的 thread **灌进一次新的 Agent 运行**。

适合给别人看、留档，或从导出的上下文另开一条*新的*会话。不适合让同事在同一段对话、同一份 diff、同一个工作目录里**接下一条指令**。

这一页不评测 Lore 的完整产品。对比的是「分享链接 / 导出」这一类，和现场工作空间交接。

## SpecStory，简要说明

[SpecStory](https://docs.specstory.com/cloud/session-sharing) 和其它会话归档一样：保存下来的历史，或公开的查看链接。查看者不会加入你正在跑的编程 Agent 会话，也拿不到会话 Worktree。把它当成历史 / 导出，而不是把人请进现场工作空间。

这个对比里，现场工作空间这一侧是 Lody。归档那一侧不是 Lody 要替代的产品。

## Lody 交接实际是什么

在 Lody 里，能打开该会话的同事可以在同一段上下文里接着做：

- Agent 已经进行过的现场对话
- Agent 改过的文件差异
- 这次会话的 Worktree 和分支
- 同一个 [Agent Config](/zh/docs/agents)，所以对方可以发送下一条提示词

对方打开的是**这个**会话——不是 Fork，也不是主页输入框里新开的一条。Fork 会把历史复制到**新的**会话；需要自己另开一条对话线时用它。见 [Fork 会话](/zh/docs/session#fork-会话)。

交接发生在团队工作空间里。对方必须已经是成员；只有会话依赖的机器（以及本地项目，如有）被共享之后，这个会话才对团队可见。步骤和边界情况见[共享并交接 Agent 会话](/zh/docs/session-handoff)。

## 什么时候用哪一种

用**分享链接、Lore 导出或 Markdown 复制**，当：

- 你只需要对方*看*发生过什么
- 你想在工作空间之外留一份记录
- 你要把导出的上下文灌进一次*新的* Agent 运行

用 **Lody 现场交接**，当：

- 同事应该接着同一个编程 Agent 会话往下做
- 对方需要当前的 diff 和同一个 Worktree，而不是靠提示词重建上下文
- 对方已经是（或可以成为）[工作空间](/zh/docs/team)成员

要以团队方式并行跑多条隔离会话——混用模型、各自 Worktree——见[并行 Coding Agents](/zh/docs/parallel-agents)。那是再开新工作，不是交接这一条。

## 权限（不要额外发明访问规则）

交接遵循产品文档里的同一套规则。这一页不会再加一套公开分享链接 ACL。

| 控制项 | 效果 |
| --- | --- |
| 工作空间成员 | 打开团队会话的前提 |
| 成员角色 | 拥有者和管理员管理谁能邀请、修改或移除成员，见[修改成员权限](/zh/docs/team#修改成员权限) |
| 机器共享 | 未共享机器上的会话不会出现在其他成员的侧边栏。只有设备所有者可以共享。 |
| 本地项目共享 | 会话使用本地项目时，同事需要同时拥有项目授权和机器授权 |
| 会话 URL | 所有者始终可用；同事仅在会话对团队可见后可用。复制 URL 不等于 **Share with team…** |

加入工作空间**不会**把你的笔记本暴露出去。机器在你主动共享之前都是私有的。共享一个会话，可能会把对应机器和/或本地项目共享给工作空间里的所有人；这台设备上的其他对话也可能随之可见。见[团队机器可见性](/zh/docs/team#团队机器可见性)。

## 常见问题

### Lore 分享链接和交接 Lody 会话是一回事吗？

不是。Lore 式链接是一份 thread 的**可查看记录**。对方可以阅读，有些流程也能从这份上下文开一次*新的* Agent 运行。他们不会加入原来的现场会话，也拿不到原来的 Worktree。Lody 交接是打开工作空间里已有的会话，让同事接着做。

### 同事能不能靠一条分享链接接着我的 Claude Code 会话？

不能靠对话记录、ChatGPT 式快照或 Lore 式链接。如果这个会话跑在 Lody 工作空间里，先邀请对方，再共享会话（以及它所依赖的机器或本地项目），然后让对方打开**这个**会话。详见[共享并交接 Agent 会话](/zh/docs/session-handoff)。

### Lody 是来替代 Lore 或 SpecStory 的吗？

不是。那些产品围绕的是可以查看或导出的记录。Lody 是会话仍在现场的团队工作空间。只需要一份记录时用分享链接。需要有人在同一个会话里接着干活时用 Lody。

### 只想发一份对话记录可以吗？

可以。复制单条消息，或在会话菜单里选择 **Copy as Markdown**。这不会授予现场访问权限。见[复制对话](/zh/docs/copy-md)。

### 为什么同事打不开我发的会话 URL？

复制会话 URL 并不等于共享会话。对方必须已是工作空间成员，机器（以及本地项目，如有）必须已共享，而且对方看的应是 **全部任务** 而不是 **我的任务**。未共享机器上的对话不会同步到其他成员的侧边栏。
