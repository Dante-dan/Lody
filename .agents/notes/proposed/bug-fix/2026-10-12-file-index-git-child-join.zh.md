# 文件系统回退前等待 Git 扫描子进程

Status: proposed
Translation: current

[English](2026-10-12-file-index-git-child-join.md)

## 摘要

文件列表命令拒绝后，扫描目前会在查询已删除文件的 Git 命令仍运行时返回。
Issue [#1507](https://github.com/LodyAI/Lody/issues/1507) 报告 Tinypool 工作线程
随后可能暂停或终止，导致子进程未及时回收。参考补丁通过 `Promise.allSettled`
等待两个命令结束再进入原有回退路径。并行执行及已删除文件的尽力过滤行为保持不变，
不修改线程池或进程接口。

## 决定与限制

工作线程与主线程回退共用扫描核心，所以由扫描核心承担等待职责。
无需改变 Tinypool atomics，也无需向已经等待进程完成的接口再添加退出监听器。
主要文件列表失败仍回退文件系统；已删除文件查询失败仍保留成功的主要列表，
延续现有行为。

现有工作线程测试增加主要命令拒绝、兄弟命令延迟结束的确定性用例，观察回退时机。
合成命令验证等待边界，不代表已验证 macOS 内核回收或生产 Nightly 的线程终止顺序。
现有 Git 工作区用例验证正常索引。上游采纳和用户公开创作对话仍待完成。
