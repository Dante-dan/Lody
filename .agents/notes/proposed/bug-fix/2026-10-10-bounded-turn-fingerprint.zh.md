# 限制 Turn 工作树指纹读取

Date: 2026-10-10
Status: proposed
Translation: current

[English](2026-10-10-bounded-turn-fingerprint.md)

## 摘要

Issue #1369 报告 Git 为未跟踪的堆转储计算哈希时，prompt 前出现数分钟延迟。当前 Turn 基线在 ACP dispatch 前为全部脏文件和未跟踪文件计算指纹，回合末的兜底统计再次计算。这次修改在两处使用最多 5 MiB 普通文件的原始内容 SHA-256 指纹。过大、不可读或读取期间变化的文件保持未知，继续显示，避免误判为未修改而隐藏。完整 daemon/ACP 积压链尚未验证。

## 证据与决定

报告者测量 11.687 GB 堆转储的 `git hash-object` 约需 312 秒，排除转储的诊断 adapter 约需 174 毫秒。这是报告者测量，并非本次复现。当前代码确实在 prompt 前等待基线捕获，包括 stale-ACP 恢复路径。

本地读取器检查文件类型与大小，最多读取 5 MiB 加一个字节，并在所有路径关闭文件句柄。大小或时间戳在读取期间变化时返回未知。原始哈希只用于私有相等比较，不是 Git object ID；避免 Git filters 也避免在 prompt 路径执行仓库配置的 filters。起始与结束使用同一读取器，无公开协议修改。

按扩展名排除会遗漏其他产物。仅用元数据可能隐藏等长内容修改；部分内容哈希可能隐藏未采样位置的修改。未知指纹保留保守归属行为：已有大产物可能显示为零行的 Turn diff，优先于隐藏真实编辑。Git status/diff 枚举与 tracked numstat 的总工作量仍未设界限，本修改只限制单文件指纹读取量。

## 验证

现有 git-diff-stats 套件增加真实文件系统回归，使用合成的 12 GiB 稀疏文件与等长源码修改。验证大产物不进入相等基线、普通编辑仍可检测、缺失和工作区外路径返回未知。不使用捕获的用户数据、真实堆转储或 ACP 对话。没有宣称完整 daemon/ACP 复现。根检查结果记录在贡献的 test plan。
