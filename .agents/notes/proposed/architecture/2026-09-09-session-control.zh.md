# 收敛会话控制、准入与失败确认

Status: proposed
Translation: pending

## 摘要

PR #517 的连续回归涉及相同的跨层边界：取消意图在传输路径被重新解释，暂停失败与请求去重没有共同所有者，停止和自动启动的准入分散。提议用一个 SessionController 统一控制请求、短临界区、暂停回执和重试，保留现有执行器、SQLite 结果存储与运行端租约。旧取消保持 turn-only，新 Stop 使用明确协商的协议；不恢复停止编号，已有用户队列仍可携带结果。本轮只产出设计及有限模型，尚未实现或验证真实进程恢复。

## 依据

基线 `eb4e02e0`，当前 [PR #517](https://github.com/LodyAI/Lody/pull/517) 有两条新的 P1：旧客户端省略 turnOnly 被接收端升级成 Stop；暂停持久化失败后 watcher 已提前去重。后者不能直接推导同一进程立即恢复投递，因为 coordinator 已保留内存门禁；真正缺口是持久化重试和恢复责任不完整。

前一阶段记录见 [操作结果暂停实现](../../implemented/bug-fix/2026-09-08-operation-delivery-pause.zh.md)。本提案独立保存，避免把尚未实施的新设计写成已有保证。

## 方案与取舍

完整设计与验收矩阵见 [会话控制设计](../../../../specs/session-control-design.zh.md)。只取消回合、停止旧自动工作、提交用户输入是三个入口；RPC 与持久 watcher 只负责传输和唤醒。请求用既有目标 Turn 与明确意图作为幂等身份，不产生停止序号。

停止确认必须来自暂停与回执的同一提交。写失败期间保留请求和门禁，Controller 主动重试；暂停未提交时，用户可编辑和排队但不启动新的 provider 输入。该取舍增加了故障期间的等待，换来旧 Stop 不会在恢复后误暂停新工作。

没有选择继续分散添加判断，因为接收端默认、确认与重试问题会继续在不同入口重复。也没有选择重写全部调度或引入新消息平台；现有会话所有权、SQLite、Loro 和 User Turn 身份可以复用。显式协议不能追溯猜出旧字符串的用户意图，因此跨版本降级能力必须如实展示。

## 验证与范围

TypeScript 有限模型放在 `specs/models/session-control-design.model.ts`，用 Node 24 直接运行。14 个事件、深度上限 12，访问 184 个状态并检查 2576 个转移；六个具体场景通过，三个故意植入的错误都得到反例。模型不覆盖实际 Loro 同步/事务/租约/鉴权/GUI，也不证明无限活性或生产实现正确。

模型严格类型检查与文档检查通过。Steer 的异步接受需要额外的转交等待状态；草案明确了接受、未送达和未知三种结果，但有限模型未覆盖它，不能用上述计数代替真实适配器验收。完整仓库运行时测试未重跑，本轮未改生产代码。

没有修改运行时代码、推送实现、解决新线程或宣称现有 PR 已具备本设计。后续应按设计中的迁移步骤进行一次完整实现与跨版本、重启集成验收。
