# 共享会话持久置顶排序参考方案

Status: proposed
Translation: current

[English](2026-10-05-durable-session-pin-order.md)

## 摘要

Issue #782 指出消息活动并不是稳定的置顶排序来源。
方案在共享元数据记录置顶转换时间，提供确定性比较器，不在读取时迁移旧会话。
补丁包含共享契约与公开桌面端元数据、排序消费层适配。
时间戳比手动排序 rank 简单，但节点时钟偏差会影响顺序。

## 决定与限制

采用需求明确接受的 `pinnedAt` 替代方案。重复置顶不改变排序，再次置顶获得新的
时间戳。旧置顶项按会话 ID 排序，不依赖消息活动或可变标题。
有序 ID 列表和分数 rank 支持手动调整，但会增加冲突消解与列表归属决策，超出本次参考范围。

公共桌面消费层 `sortUpdatedItems` 和会话列表树排序共同使用置顶转换时间，
行投影保留新元数据；平面行和 opened-by 根组均不以消息更新移动置顶顺序。
未置顶项仍按活动排序。移动消费层及外部 Inbox 需要各自的适配。
[草稿 Spec](../../../../specs/session-pin-order.zh.md) 记录拟议保证。
不声称已经人工批准或完整解决 issue。

## 验证

共享包与桌面端的 Vitest 行为检查覆盖消息更新、重复置顶、重新置顶与旧数据回退。
实际执行结果记录在贡献报告；方案仍待评审，移动端接入尚未完成。
