# Codex 项目历史的选择性自动导入

Status: proposed
Type: feature
Translation: current
Issue: [#1396](https://github.com/LodyAI/Lody/issues/1396)

[English](2026-10-12-codex-project-auto-import.md)

## 摘要

Codex Desktop 用户希望已有聊天直接出现在 Lody 中，而无需逐个选择。本参考实现为已登记的本地项目和选定的原生 Codex 提供方增加默认关闭的偏好。打开该项目的对话列表、使其重新可见或手动同步时，先列出提供方的项目目录，再通过现有只读导入器导入新出现的对话。已有导入和冲突被保留；不发现其他账户、不扫描全局 home，也不运行后台监听。真实 Codex Desktop 数据发现仍未验证。

## 证据与范围

现有界面将目录同步与导入所选 ID 分开。Codex 适配器的 `thread/list.sourceKinds` 已包含 `appServer`，但会按请求的项目目录及所选模型提供方过滤。包含该来源只是代码证据，不能证明选定原生 home 能看到每个 Desktop 对话。

受管理的 Codex profile 特意不拷贝全局历史和原生会话数据库（[profile 意图](../../../../specs/codex-account-profiles.md)）。因此开关仅面向 Electron、本机及明确选定且不带 `codexAuth` 的 builtin Codex 配置。远程目标、受管理 profile、缺少明确配置的旧请求及其他 agent 不显示开关。原生目录没有建立可用于筛选的账户 ID；在 Lody 外切换登录后，同一非托管提供方内的历史隔离未获证明。现有数据归属和只读回放边界保持；没有引入需要新 Spec 的数据源、归属保证或耐久协议。

## 决定

渲染器按用户、工作区、机器、本地项目及提供方 ID 保存同意，不向共享项目元数据写入同意。偏好属于当前渲染器，并在重新打开列表后保留，不是 daemon 计划。只有当前显示的提供方列表触发自动工作。

目录读取仍使用选定的提供方和项目。仅选择 available 项（含无状态的旧项）。稳定导入 ID、持久历史与 cursor、账户绑定及冲突检测继续由现有机器导入器负责。已导入会话继续在打开时刷新；冲突继续要求现有明确替换操作。

每个设置 owner 对同一项目和提供方只接纳一个历史操作。关闭开关、离开对话列表、销毁设置、切换用户或工作区、删除项目或失去选定的原生配置，会停止接纳后续自动批次。已经接纳的批次可以完成，已持久导入保留。错误继续使用现有错误及逐批结果界面。重新打开列表或明确同步可重试；不增加轮询 timer 或无人值守重试。

## 验证与限制

现有 control-client 测试覆盖只导入可用项、保留冲突及已有导入、明确本机原生提供方准入、拒绝受管理/远程/不明确提供方，以及在有界批次之间关闭开关。现有 panel 测试覆盖默认关闭和在 pending read 期间关闭后取消导入。ProjectSettings Storybook 包含可交互的合成导入状态。

12 项定向测试、受影响包类型检查、根工作区类型检查、修正后的类型感知 lint、格式、文档及边界检查通过。全量 CI 测试命令在已有 CLI fixture 尝试写入真实用户数据目录遭 sandbox 拒绝后中断；当时超时的两项 UI 测试在参考树上独立重跑通过。这不表示全套测试通过，也不是基线对比。测试 revision 随公开参考交付记录。未使用真实账户、私人 transcript，也未验证真实 Desktop 导入、远程机器、后台同步、任意项目重新归属或新数据源。本实现是 #1396 的第一步，不表示自动同步需求已全部解决。
