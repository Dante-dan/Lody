# 项目分组参考模型

Status: proposed
Translation: current

[English](2026-09-30-project-groups.md)

## 摘要

Issue #1144 希望跨本地项目和会话进行组织，同时保持执行归属不变。
首个提议切片使用包含机器身份的项目引用与现有会话身份。
不可用成员留给调用方的解析层处理，不会被静默移除。
有界存储层在既有工作区文档中保存独立成员行，并导出先保证本地持久化的 Repo 调用。
导航和命令尚未实现；本次没有交付完整功能。

## 决定与证据

机器 Flock 已拥有本地项目，工作区 Flock 已拥有共享目录。
把根路径移入分组或修改 ProjectRef 会混淆组织和执行。
因此参考模型仅保留 ID，访问检查仍由现有读取器负责。
存储实现使用独立成员行保留并发添加，而非整体持久化读取投影数组。

以项目路径或名称作为身份会丢失机器身份；隐藏不可解析成员会把离线表现成删除。
模型避免两者，不修改执行协议；[Spec](../../../../specs/project-groups.zh.md) 保持草案。

## 验证边界

仓库 Vitest 测试覆盖机器限定身份、不变更新的添加与移除、幂等、不可用成员保留，
以及未绑定项目的会话引用。不声称已验证界面、CLI 或离线机器端到端行为。
代码是导出的有界存储提案；不声称人工 Spec 批准或已提交 PR。

2026-09-30 使用 Vitest 3.2.4 运行定向测试，三个测试全部通过。
参考实现和测试使用仓库要求版本的 Oxfmt 格式化。完整工作区依赖恢复未能完成：
Codex 子模块清单要求的版本高于根锁文件，仓库的最小发布时间策略又拒绝该新版本。
因此完整仓库 check/format 未通过，定向测试不代表集成验证。文档检查通过。

扩展后的原有测试组六项通过，覆盖独立成员行合并、无效/孤立行、精确删除以及上传失败后的本地持久化。
工作区文档 ID 构造函数移入无依赖模块，原 API 保持重导出。
未改根锁文件、执行对象、MCP/Role 模式或平台组合。

尝试了严格 TypeScript 切片检查，但既有共享包传递导入缺少工作区依赖，无法完成。
不声称包级或工作区类型检查成功。
