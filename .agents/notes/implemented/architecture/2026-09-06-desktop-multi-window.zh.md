# 桌面多窗口的归属与状态隔离

Status: implemented
Translation: current

[English](2026-09-06-desktop-multi-window.md) | 中文

## 摘要

多个桌面窗口需要分别确定窗口内导航、文档副本缓存和工作区级后台任务的归属。
额外的产品 Renderer 隔离布局与缓存状态，同时保留相同的逻辑工作区和 CLI 执行服务。
Electron 主进程为每个工作区指定一个后台任务负责窗口，并校验拖出请求，避免新增视图同时成为额外的通知生产者或执行服务。
隔离的代价是更多 Renderer 内存与缓存存储；Linux 交互检查已通过，但量化收益及 macOS/Windows 原生行为仍未验证。

## 决策与取舍

- 明确请求打开 Session 时创建新窗口，同一 Session 可重复打开。它不移动、复制、归档 Session，
  也不改变来源窗口的导航。导航侧栏及右面板默认关闭，并携带一次性的输入框聚焦意图；用户仍可
  展开导航。仅指定工作区时打开 Chat Landing。复用已有窗口无法提供另一份独立视图；实现不承诺
  应用重启后恢复所有附加窗口。
- 修饰键点击、行的更多/右键菜单和 Session 页头菜单共用开窗路径。只有侧栏 HTML5 拖拽参与拖出
  开窗；已接受的提及拖放和标签栏排序保持原有行为。主进程消费一次性令牌、取消状态和原生
  光标/窗口边界证据，而不是把每次 Renderer `dragend` 都视为开窗请求。
- 目标包含工作区，以及可选的根 Session 和精确子标签，不接受任意 URL。
  显式 `?tab=session:…` 避免最近标签恢复覆盖指定对话。附加窗口复用带安全保护的产品窗口工厂；
  原生菜单、对话框及公共浏览器视图分别解析其所属窗口。
- 桌面导航收起状态使用窗口 `sessionStorage`；附加窗口的草稿、标签和面板状态也使用它，
  不覆盖主窗口的最近路由。跨 Renderer 共用这些 UI 键会耦合本应独立的视图。
- 附加 Renderer 的 Repo、游标及预取高水位缓存使用独立命名空间，而不是不同的逻辑工作区身份、
  传输或 CLI 实例。这避免多个活动副本共用一个持久化身份；代价是重复缓存和可能更冷的首次加载，
  不代表新增 Renderer 没有成本。
- 主进程按注册顺序为每个工作区选择第一个窗口负责后台任务，不按操作系统焦点选择。注册、工作区
  变化和窗口销毁都会重新计算归属。通知、角标及工作区监听跟随该归属；提前预取还要求导航侧栏
  有效可见以及文档可见。隐藏导航不会停止当前对话或其 Agent。已隐藏但仍注册的主窗口可能继续
  负责后台任务。
- 可选组织激活解析调用窗口所指定的组织，不修改账户级活动组织。这不会为公开本地组合开启托管
  操作，也不绕过成员权限检查。退出登录和已确认的缓存重置关闭其他产品窗口，以释放残留的已认证
  视图或未关闭的缓存连接。

## 验证与限制

纳入源码的覆盖包括[目标/拖拽测试](../../../../apps/electron/src/main/app-window-target.test.mjs)、
[行与工作区快捷操作](../../../../packages/components/tests/sidebar-mark-unread-menu.test.tsx)以及
[存储隔离](../../../../packages/components/tests/desktop-window-storage.test.ts)。Electron 的 95 项测试通过。
使用隔离合成 Agent 的 Linux Electron 检查验证了快捷键及菜单开窗、来源导航不变、输入框聚焦、
侧栏状态独立、共用 CLI、原生鼠标拖出，以及主窗口关闭后的后台任务交接。
这项临时验收并不是新增的、已提交的跨平台端到端场景。

实现过程中构建、类型和边界检查通过。全量测试并未全绿：15 个套件因侧栏初始化在无浏览器环境下
访问浏览器存储而无法加载，另有一个头像缓存时序断言失败。初始化已修正为在 Electron 之外保留
可安全用于无浏览器环境的默认存储；随后全部 16 个受影响套件复跑通过，共 136 项测试。
之后没有重新运行完整流水线。

macOS/Windows 原生拖拽、全屏与多屏行为，可选托管模式多工作区集成，以及内存/CPU 收益的量化
仍未验证。既有能力开关仍然适用；本文不代表行为 Spec 获得批准。

## Review 修正（2026-09-08）

审查发现侧栏可见性被错误地用作工作区 Task Index 的生命周期：隐藏导航会清空任务行和
打开的任务标签，而仍可见的 Tasks 列表、看板和状态 watcher 也依赖这些数据。
现在只要工作区就绪且 Tasks 开启，就保留索引同步，不依赖侧栏可见性或后台任务归属。
保留这份共享投影需要一项订阅，但能保住可见 UI 和 watcher 的输入；侧栏可见性只能暂停
侧栏专属工作。工作区失效和关闭 Tasks 开关时仍然清理。

Windows/Linux 的“窗口 → 关闭窗口”菜单也残留了固定关闭主窗口的回调。
现在优先关闭菜单目标窗口，仅在没有目标时使用当前原生焦点；无焦点时不执行操作。
这是整窗关闭，与 Ctrl+W 优先关闭标签的行为不同，后者未改动。

[索引生命周期测试](../../../../packages/components/tests/main-layout-task-index.test.tsx)
使用真实布局和同步 hook、合成索引数据源，检查任务行、打开标签、隐藏期间更新、Zen、
工作区就绪状态和 Tasks 开关。
[菜单测试](../../../../apps/electron/src/main/menu.test.mjs)使用 Linux/Windows 原生 API
替身执行真实菜单模板。恢复原代码后，任务回归和全部四项菜单测试都失败；恢复修复后通过。
这些是定向回归，不是新增 Windows/macOS 原生验收或仓库全量通过的声明。
此前原生拖拽的不确定性保持不变。
