# 临时关闭会话写前全状态校验

Status: implemented
Translation: current

[English](2026-09-07-temporary-session-validation-bypass.md)

## 摘要

发送合法消息时，Mirror 会用当前客户端的 schema 重新校验无关旧历史，从而阻塞发送。
仅接受未知 item 的类型名不够：未知 item 的 `text` 如果是对象，仍会被已声明的字符串字段拒绝。
因此前端与 CLI 的会话 Mirror 暂时关闭写前全状态校验，恢复写入。外部输入解析保持不变，
但内部新写入会少一道防止错误数据落盘的检查；这不是已完成的类型安全 writer 或容错 reader 方案。

## 决定与范围

[PR #460](https://github.com/LodyAI/Lody/pull/460) 在两处生产 `sessionDocSchema`
Mirror 构造点设置 `validateUpdates: false`，其他文档不变。Schema 仍决定存储布局，
显式 schema/Zod 检查仍然可用。本次不新增迁移、历史清理或 writer。

已复现仅放行未知类型名仍然失败。即使单独绕过未知类型检查，损坏的已知类型历史也会阻塞
无关写入。这次临时优先恢复会话可用性，等待已有 HistoryWriter 工作推进，不依赖 #443 或 #359。

## 替换条件与代价

本临时决定中历史写入的部分已由[共享 HistoryWriter](../architecture/2026-09-07-single-history-writer.zh.md)
替代。下列条目记录原先“仅关闭校验”的代价，不是新的写入契约。

- 用明确类型的局部 HistoryWriter 操作替换，覆盖前端、CLI 和功能开关回退路径。
  不能只因主视图换了 writer，就恢复发送时的全历史校验。
- 预计短期使用，但不设置按时间自动恢复的开关。
- 绕过外部输入解析的内部错误新值可能落盘。本次没有新增字段隔离、诊断或
  “非法字段更新保留旧值”机制。
- 存储映射、diff、读取和渲染仍可能失败。此开关只消除全状态校验造成的拒写，
  不保证所有发送失败都消失。

## 证据与边界

使用合成数据和真实 Loro 双副本，覆盖实时同步、快照重开、带对象型 `text` 的未知类型，
以及损坏的已知 text item。加开关前四个用例被全状态校验阻断，加开关后通过。
断言包括：追加后旧轮次 JSON 不变、快照打开及读取不产生写入、合法用户消息追加、
相邻文本修改、未来字段并发修改、双副本收敛及未来容器 ID 保留。
构造点检查覆盖前端和 CLI 配置；显式输入解析仍拒绝损坏及未知的新 item。

测试复用了本地已有依赖树中的 Loro 1.15.1 / Mirror 2.3.1。
这不等于完整应用入口测试、已发布旧二进制测试，也不是桌面、移动端或 3000 轮端到端验收。
现有 CLI 历史清理逻辑未改；这里“不重写”的测试结论限于这些 Mirror 操作，
不能推广为所有应用启动路径的保证。
