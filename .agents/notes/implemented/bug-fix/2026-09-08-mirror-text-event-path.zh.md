# Mirror 文本事件的路径复制

Status: implemented
Translation: current

[English](2026-09-08-mirror-text-event-path.md)

## 摘要

接入局部写入后，单个文本片段的大部分时间仍花在 Mirror 从整个状态根节点进入 Immer 的更新中。
这次为固定版本 Mirror 2.3.1 添加补丁，只复制已有文本节点的祖先路径，复用未改分支并保留属性描述符。
复杂事件继续使用原实现。它改善单文本路径，不改变存储或通知；整段导入和应用端到端性能仍需分别解决。

## 决策

这是[局部流式写入](2026-09-08-targeted-history-streaming.zh.md)的后续，不是第二个 writer，也没有接入
ConversationView。优化放在 Mirror 的事件应用内部，因此本地 writer 提交和远端导入都可能获益。
沿用原文本 delta 算法，保留不可枚举、只读的 `$cid`。不修改旧快照、不抑制 commit、不绕过解析，
也不省略订阅通知。存储仍是 Loro 1.15.1 和既有 schema。

仅当批次只有一个文本事件、旧值是字符串、路径由普通对象或数字数组索引组成时启用。
缺少旧值、树节点 ID、访问器属性和结构性／多事件批次继续走原实现。
复制数组祖先仍与其宽度有关，不是任意历史访问 O(1)。使用属性描述符复制而非对象展开，
以保留容器身份并避免触发 getter。

补丁同时包含源码和发布 JavaScript，由 lockfile hash 固定，可以独立于历史存储 schema 撤回。
未来 #443 的存储提示和配套 Mirror 补丁必须与本补丁合并，不能互相覆盖。
本地接入补丁不表示已经发布依赖或创建上游 PR。

## 证据与剩余工作

合成基准接受 `HISTORY_BENCH_BASELINE_ENTRY`，指向解包的未修改 2.3.1 入口。
交替运行旧／新 reader，使用同一份当前 writer，核对完整存储和读取 JSON，
并用两个真实副本验证旧／新 reader 下并发字段及文本修改。计时分开记录输入准备、容器创建和
commit／订阅处理。耗时观察不是测试阈值。
最终比较每组对照使用新进程（`HISTORY_BENCH_SAMPLES=1`、`HISTORY_BENCH_SAMPLE_OFFSET=0|1|2`、
`HISTORY_BENCH_PAIRED_ONLY=1`），每个 view 都 dispose，每个文档显式 free。
Node 在同一长进程内重复 seed 时，即使显式 free／GC 仍逐渐变慢，底层原因在本轮尚未完全定位。
使用进程隔离是为了让测量不依赖这种回收行为，不表示修复了生产生命周期。

回归覆盖 Unicode 文本、旧快照不变、兄弟分支引用复用、`$cid` 描述符、同步订阅、
后续 Mirror 自身写入、远端插入删除、混合事件、根文本和树路径回退。
发布包自带的事件测试验证补丁源码，仓库测试验证实际发布 JavaScript。

Bun 1.3.14 串行、新进程对照，三组样本、每组 30 个片段、不另设预热，
每组平均片段耗时的中位数（毫秒）：

| 历史条数 | 未打补丁 reader | 打补丁 reader |
| --- | ---: | ---: |
| 50 | 1.060 | 0.189 |
| 200 | 3.839 | 0.156 |
| 400 | 6.067 | 0.180 |

两边使用同一个局部 writer，不是比较不同的写入 API。200 条时，新版 seed 分段中位数约为
输入准备 13ms、容器创建 330ms、commit／订阅 555ms。启动和顺序效应会影响 seed 数字；
没有证据说明本补丁改善了整段 seed。早先同进程 Bun 对照的 400 条结果是 3.486ms 对 0.139ms，
不能混用不同测量方式的数字。
完整 `pnpm check`、上游 21 个事件源码测试、源码严格类型检查、格式、文档和 frozen lockfile-only
校验通过。沙箱禁止本地 socket 导致的测试失败在允许本地绑定后重跑通过，没有删除或放宽测试。

整段 seed 仍需创建大量嵌套 Text／Map／List 并构建读侧状态。分段测量中，输入解析并非主要耗时。
没有在缺少 schema 注册顺序安全证明时删除第二遍注册，也没有为优化数字而改变存储布局。
单文本路径变快不能证明真实桌面／手机 3000 轮验收通过，更不能代表整个应用已经快了 10 倍。

Node 24.20.0 配合 tsx、每组对照新进程、200 条历史的单文本中位数为：未打补丁 5.225ms，
打补丁 0.181ms。Bun 和 Node 是不同运行时的测量，都没有运行实际桌面／手机 UI 或完整生产订阅集合。
